# 范文夹：AI 识别多词搭配与选区批注签设计

## 目标

让读者在范文正文中选择包含三个或更多英文单词的片段后，主动请求智谱识别其中真正值得记忆的搭配，而不是被迫把整段原文当作短语保存。

例如，选择 `combining practical experience with academic study` 后，建议学习内容可以是 `combining … with`；原始选区仍保留，用于定位正文与还原语境。

## 范围

- 仅修改独立站点 `composition-site/`，不改动旧项目的前后端、账户或数据。
- 保留现有单词悬浮释义、点击单词记笔记、短语笔记和原生复制能力。
- 使用现有服务端智谱调用；浏览器不接触 API Key。
- 本次不做全文预分析、自动批量记笔记或跨作文词库。

## 交互设计

### 选区与批注签

1. 读者在正文中做原生文字选择。只有清理首尾空白和终止标点后，仍是连续英文词组且至少两个词时，才展示操作入口。
2. 桌面端使用 A 方案「书页批注签」：选区稳定后，纸签贴在选区最后一行附近，显示选中词数和主操作。
3. 移动端不干扰系统选择手柄；停止拖动约 200ms 后，在安全区域底部显示同一操作条。
4. 两词短语保留现有“解释并记下”路径。三个或更多词的主操作显示为“识别搭配并记下”。
5. 批注签不抢走选择焦点，Ctrl/Cmd+C 仍可复制；键盘 Shift 选择同样适用；Esc 只收起批注签。
6. 正文中的原生选区使用范文夹的淡金色半透明底色和深绿色文字，不使用默认电脑蓝色选中框。它只改变选中时的视觉，不改变拖选、复制、键盘选择或取消选择后的正文样式。
7. 该选区样式只作用于范文正文；在系统强制高对比度模式下不覆盖系统颜色，以保证无障碍可读性。移动端的文字选择手柄仍由系统控制。

### 多词 AI 识别流程

1. 选择超过两个英文单词时，界面立即显示批注签，但**不调用 AI**。
2. 读者点击“识别搭配并记下”后，立即打开笔记弹窗，首先显示原文选区、语境和可编辑的“学习内容”输入框；输入框初始值为清理后的原文选区。
3. 输入框上方提供一对小型切换按钮：
   - **保存原文**：将输入框明确切回清理后的原文选区，并标记为当前保存方式。
   - **保存搭配**：将输入框明确切换为智谱建议的学习搭配，并标记为当前保存方式。
   - 两个按钮可来回切换；按钮只在读者主动点击时改写输入框。读者手动编辑后进入“自定义”状态，仍可随时点任一按钮恢复对应内容。
4. 同一次语境释义请求返回中文释义、记忆提示和建议学习搭配。请求完成后：
   - 默认保持“保存原文”，不会因为 AI 返回而自动改写输入框。
   - “保存搭配”从加载态变为可用；点击后才把 AI 建议写入输入框。
   - 若智谱不可用或没有有效建议，“保存搭配”保持不可用并说明可继续保存原文或手动编辑。
   - 释义、记忆提示仍遵循现有“不覆盖用户已填内容”的规则。
5. 读者可在智谱尚未返回、返回失败或建议不满意时，直接改写“学习内容”并保存。
6. 保存后，短语笔记列表用最终“学习内容”作为主标题；若它与原文选区不同，标题下显示简短的“原文：…”辅助行。点击定位仍依据原始选区的范围，不会丢失上下文。

## AI 输出与防护

扩展现有 `POST /api/compositions/{id}/explanations` 的响应，不新增浏览器直连端点。请求仍只提交起止偏移、类型、正文版本和可选的 `generateLearningText` 标记；服务端重新从当前用户的作文正文解析选区和句子。

`generateLearningText` 默认是 `false`。单词悬浮、单词笔记和两词短语继续走基础释义；仅点击三个或更多词的“识别搭配并记下”时传 `true`。释义缓存必须区分基础结果与增强结果，不能把一个没有 `learningText` 的基础缓存误当作已识别的搭配结果。

响应新增可选字段 `learningText`：

```json
{
  "selectedText": "combining practical experience with academic study",
  "kind": "phrase",
  "translationZh": "将实践经验与学术学习结合起来",
  "memoryHint": "combine A with B：把 A 与 B 结合",
  "learningText": "combining … with",
  "contentVersion": 1
}
```

智谱提示词规则：

- 仅在短语且原文至少三个英文词时，识别一个简洁、可复习的英语学习表达。
- 如果选区包含成熟的不连续搭配，可用一个或少量 `…` 代替可变中间成分；固定词必须来自原文。
- 如果不存在清晰的搭配，返回清理后的原文选区，而不是猜测或杜撰。
- 单词和两词短语不请求 `learningText`；旧请求或旧记录缺少该字段时，前端以原文选区作为回退显示。
- 服务端对模型输出做长度、空白和字符规范化（包括将 `...` 统一为 `…`）；无效的 `learningText` 一律回退为原始选区，不影响释义的正常返回。
- 选区、句子均明确标记为待分析数据而非指令，维持现有提示注入边界。

现有 24 小时按作文版本与选区范围缓存继续适用，因此同一选区反复打开不会重复消耗模型调用。

## 数据模型与保存语义

为 `composition_annotations` 增加可空 `learning_text`（最长 500 字符）：

- `selected_text`、`start_offset`、`end_offset`、`content_version` 保持原样，始终代表正文中实际选取的内容。
- `learning_text` 代表用户最终决定记住的表达。短语保存时由可编辑输入框提交；单词可为空。
- 对同一作文、版本和范围的再次保存是更新，更新释义、笔记和 `learning_text`，不会创建重复条目。
- 后端仍校验范围、版本、所属账户和选区类型；不会信任客户端提交的原文文本。

## 边界行为

- 含中文、跨句、非连续英文词、只选到半个词或末尾只有标点的情况，不展示可保存的短语入口；原生选择保持不受影响。
- 末尾逗号、句号、引号和多余空白会被从候选短语中剔除，并以清理后的范围参与保存，避免“看起来对、保存范围错”。
- 多行选区按最后一个客户端矩形定位批注签；视口边缘会自动翻转/夹紧，避免遮挡文本。
- 关闭弹窗、切换作文、正文版本冲突或登录失效时，异步返回结果不得写入错误的笔记。
- 智谱不可用时继续允许手填释义、学习搭配和记忆提示；只给出非阻塞提示。

## 验收与测试

- 前端单元测试覆盖候选短语清理、词数阈值、原生选区稳定延迟、学习搭配回退，以及“保存原文 / 保存搭配 / 手动编辑”三种输入状态。
- 前端 UI 合约测试覆盖批注签、学习内容输入框、双切换按钮、正文专属选区样式、可访问性标签和保存载荷。
- 后端测试覆盖：模型返回搭配、无效搭配回退原文、缓存、未配置时 503、注释新字段持久化、同范围更新、账户隔离和正文版本冲突。
- 人工浏览器验收覆盖桌面单行/多行选择的金色选区、移动选择、两词与三词以上路径、`combining … with` 示例、原文/搭配来回切换、复制、Esc、慢响应与模型不可用时手动保存。

## 明确不做

- 不在选择时自动发起智谱请求。
- 不把模型建议当作不可改的正确答案。
- 不删除原始选区或用 AI 输出替代正文定位信息。
- 不在浏览器、静态资源、测试夹具或文档中保存任何 API Key。
