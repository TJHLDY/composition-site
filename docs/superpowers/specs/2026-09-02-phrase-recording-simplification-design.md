# 范文夹：短语记录简化设计

## 目标

取消 AI 固定搭配识别，保留正文原生拖选、暖金色选中特效、普通短语释义和短语笔记。

## 已确认交互

1. 读者在范文正文中拖选两个或更多连续英文词后，保留原生文字选择与暖金色高亮。
2. 批注签只显示 `已选中 X 个词`，主按钮统一为 `记录短语`；桌面端靠近选区最后一行，移动端位于底部安全区。
3. 点击 `记录短语` 后，弹窗只展示原始选区、普通语境释义和记忆提示输入区。它不显示“学习内容”、`保存原文`、`保存搭配`，也不尝试生成搭配。
4. 新短语笔记以正文实际选中的原短语保存；短语释义仍由现有服务端翻译路径提供。
5. 旧笔记中的 `learningText` 继续读取和显示，避免篡改用户过去保存的数据。新前端编辑旧笔记时，未提交该字段不得把旧值清空。
6. 请求释义时，“正在按本篇语境生成释义…”显示为暖色状态卡和克制的呼吸提示；结果、失败、关闭弹窗后恢复为普通辅助文案，并尊重系统的减弱动画设置。

## 兼容与边界

- 仅修改 `composition-site/`，不修改 `vocabulary/` 或 `vocabulary-frontend/`。
- 旧客户端若仍发送 `generateLearningText: true`，服务端把它视为普通释义请求，不再触发搭配识别；这样不会因版本交错而报错。
- 历史数据库的 `learning_text` 列和 API 读取字段保留；本次不做数据迁移或删除。
- 继续保留短语末尾标点清理、真实偏移计算、原生复制、Esc 收起批注签、强制高对比度回退和移动端安全区定位。

## 验收

- 两词、三词及更多英文词的批注签文案一致，均为“已选中 X 个词 / 记录短语”。
- 浏览器请求不再包含生效的搭配识别路径；即使旧请求带该标记，服务端也只返回普通释义。
- 记录短语弹窗没有搭配切换控件，新短语保存后主标题是原始选区。
- 旧 `learningText` 笔记继续显示，重新保存普通释义或记忆提示不会清空它。
- 语境释义加载文案在等待期间比普通辅助文案更醒目，且不造成持续的强烈动画。
- 暖金色选中特效在桌面与移动端保留；前后端自动化测试和真实浏览器路径通过。
